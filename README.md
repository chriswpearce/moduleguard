# ModuleGuard

ModuleGuard converts a single-file Python module into an import-compatible Windows native module protected by a signed, portable, time-limited licence.

The protection process automatically:

1. removes comments and docstrings;
2. scrambles eligible parameter and internal variable names;
3. adds an import-time licence check; and
4. compiles the result with Nuitka and Zig into a `.pyd` and installable `.whl`.

Existing imports remain unchanged. For example:

```python
from pricing_rules import calculate_price
```

ModuleGuard licences are **portable**. They are not tied to a computer and no activation request is required. Anyone who has both the protected module and a valid licence can use them on a compatible computer until the licence expires.

> ModuleGuard makes casual source inspection substantially harder, but it cannot make reverse engineering impossible.

## What is required

### Publisher

The publisher protects modules and issues licences. The publisher needs:

- Windows x64;
- CPython 3.9 or later;
- permission to install Python packages with `pip`;
- the ModuleGuard project or wheel;
- the source module and its dependencies; and
- the encrypted private signing key.

ModuleGuard installs Nuitka and Zig as Python packages. It does not require administrator permission or a system-wide compiler.

### End user

The end user needs only:

- the protected `.pyd` or `.whl`;
- the portable `.lic`;
- the matching CPython minor version and Windows architecture;
- `cryptography`; and
- the protected module's normal dependencies.

The end user does **not** need ModuleGuard, a compiler, or a private key.

## Quick start for publishers

These examples use:

| Setting | Example |
| --- | --- |
| Source | `C:\PrivateSource\pricing_rules.py` |
| Module name | `pricing_rules` |
| Product ID | `pricing-rules` |
| Product version | `1.0.0` |
| Release folder | `release\pricing-rules-1.0.0-py39` |

Run commands from the ModuleGuard project folder. The commands below work in both PowerShell and Command Prompt.

### 1. Install ModuleGuard

From the project source:

```text
python -m pip install -e ".[test]"
```

Alternatively, install the ready-made tool wheel:

```text
python -m pip install "dist\moduleguard-0.3.0-py3-none-any.whl"
```

The `dist` folder is generated by `python -m build --wheel`; it is not required in the source repository.

Publishers should run the tests before releasing protected software:

```text
python -m pytest -q
```

### 2. Create signing keys once

```text
python -m moduleguard keygen --private-key ".local\pricing-rules.private.pem" --public-key ".local\pricing-rules.public.pem"
```

ModuleGuard asks for a private-key passphrase twice. This creates:

- a private key used to issue licences; and
- a public key embedded in protected modules to verify licences.

Keep the private key and passphrase out of release folders, source control, shared repositories, scripts and logs. Back up the private key in an approved encrypted location.

### 3. Protect the module

```text
python -m moduleguard protect --source "C:\PrivateSource\pricing_rules.py" --module-name "pricing_rules" --product-id "pricing-rules" --product-version "1.0.0" --public-key ".local\pricing-rules.public.pem" --output-dir "release\pricing-rules-1.0.0-py39" --dependency "numpy>=1.26"
```

Repeat `--dependency` for every third-party runtime dependency. ModuleGuard adds `cryptography>=41` automatically.

The release folder contains:

| File | Purpose |
| --- | --- |
| `pricing_rules.cp39-win_amd64.pyd` | Native drop-in module. |
| `moduleguard_protected_pricing_rules-1.0.0-cp39-cp39-win_amd64.whl` | Recommended installable package. |
| `moduleguard-release.json` | Release details and SHA-256 checksums. |

The original source is not modified or included in the release.
The release folder is generated distribution output and is not required in the source repository.

### 4. Issue a portable licence

```text
python -m moduleguard issue --product-id "pricing-rules" --private-key ".local\pricing-rules.private.pem" --product-version "1.0.0" --duration "1mo" --output "release\pricing-rules-1.0.0-py39\pricing-rules.lic" --ledger ".local\issuance-ledger.jsonl"
```

ModuleGuard asks for the private-key passphrase and signs the product ID, product version, validity dates and any optional website or file-system access requirement.

> **Licence filename requirement:** unless `MODULEGUARD_LICENSE_FILE` is set, the licence filename **must** be the protected product ID's safe filename form followed by `.lic`. The product ID is the value supplied to both `moduleguard protect --product-id` and `moduleguard issue --product-id`. The licence file's name is independent of the private-key filename and the name of the person or computer issuing it.

For example:

| Product ID used during protection | Required licence filename |
| --- | --- |
| `pricing-rules` | `pricing-rules.lic` |
| `element_library` | `element_library.lic` |

Therefore, a licence for product ID `element_library` named `vector_lib.lic` will not be found automatically, even when it contains a valid signature and the correct product ID. Rename it to `element_library.lic`, or set `MODULEGUARD_LICENSE_FILE` to its full path.

For example, to use `C:\CompanyLicences\vector_lib.lic` without renaming it, set the environment variable before starting the protected application:

```powershell
# PowerShell
$env:MODULEGUARD_LICENSE_FILE = "C:\CompanyLicences\vector_lib.lic"
python "C:\Applications\run_report.py"
```

```batch
rem Command Prompt
set "MODULEGUARD_LICENSE_FILE=C:\CompanyLicences\vector_lib.lic"
python "C:\Applications\run_report.py"
```

These commands set the variable for the current terminal session. The path must include the licence filename, not only its containing folder.

Characters that are unsafe in a Windows filename are converted when ModuleGuard calculates the safe filename. Use the `license-path` command to display the exact expected name and central path:

```text
python -m moduleguard license-path --product-id "pricing-rules"
```

A licence may have any filename only when its full path is supplied through `MODULEGUARD_LICENSE_FILE`. The signed product ID inside the licence must still match the product ID embedded in the protected module.

### 5. Inspect the release

```text
python -m moduleguard inspect --release-dir "release\pricing-rules-1.0.0-py39" --forbid-text "a distinctive confidential phrase"
```

`--release-dir` identifies the folder containing the `.pyd`, `.whl` and release manifest.

`--forbid-text` scans every release file for the exact UTF-8 text and fails the inspection if it is found, making it useful for checking that a distinctive confidential source phrase was not embedded in the distributed artefacts; repeat the option to check multiple phrases.

## Optional access requirement

A licence can optionally require either:

- a website to load; or
- an absolute file or folder path to be accessible and openable.

The two requirements are mutually exclusive: one licence cannot use both `--required-url` and `--required-path`.

### Website

A licence can require a website to load successfully whenever the protected module is imported. This can be used as a basic network-presence check.

```text
python -m moduleguard issue --product-id "pricing-rules" --private-key ".local\pricing-rules.private.pem" --product-version "1.0.0" --duration "1mo" --required-url "https://snclgroup.sharepoint.com/sites/intranet-home" --output "release\pricing-rules-1.0.0-py39\pricing-rules.lic"
```

The URL:

- must be an absolute `http://` or `https://` URL;
- must not contain embedded credentials;
- is stored inside the signed licence and cannot be changed without invalidating the signature; and
- is requested with a five-second timeout whenever a new Python process imports the protected module.

The import succeeds when the URL request completes with an HTTP success or redirect response. It fails closed if the site cannot be loaded.

### Important limitation

This is an availability check, not strong user or network authentication. A SharePoint address may be reachable outside the company network and may redirect to a public Microsoft sign-in page. In that case, it may load successfully without proving that the user is connected to the intended network.

For a meaningful network check, use an organisation-controlled HTTPS endpoint that is reachable only from the approved network or VPN. Do not use a critical business page whose availability may be intermittent. If no network restriction is needed, omit `--required-url`.

### File or folder path

Use `--required-path` to require access to an absolute local, mapped-drive or UNC path. The value is stored inside the signed licence and cannot be changed without invalidating its signature.

Folder example:

```text
python -m moduleguard issue --product-id "pricing-rules" --private-key ".local\pricing-rules.private.pem" --product-version "1.0.0" --duration "1mo" --required-path "P:\ExampleCorp\ProtectedResources" --output "release\pricing-rules-1.0.0-py39\pricing-rules.lic"
```

File example:

```text
python -m moduleguard issue --product-id "pricing-rules" --private-key ".local\pricing-rules.private.pem" --product-version "1.0.0" --duration "1mo" --required-path "P:\ExampleCorp\ProtectedResources\access-marker.txt" --output "release\pricing-rules-1.0.0-py39\pricing-rules.lic"
```

Whenever a new Python process imports the protected module, ModuleGuard:

- opens a required file in read-only binary mode and reads at most one byte; or
- opens a required folder for directory enumeration.

The import fails if the path does not exist, is disconnected, is the wrong type, or the current Windows account lacks access. ModuleGuard does not modify the file or folder. Mapped drives such as `P:` are specific to the current Windows logon and may not exist for scheduled tasks, services or other users; a UNC path may be more reliable in those situations.

This is an access check, not proof of user identity. Anyone who can access the specified path satisfies the condition. If no file-system restriction is needed, omit `--required-path`.

## Distributing and using a protected module

There are two supported approaches.

### Option A: keep the licence beside the `.pyd`

Place these files together in the application or tools folder:

```text
pricing_rules.cp39-win_amd64.pyd
pricing-rules.lic
run_report.py
```

The application imports the module normally:

```python
from pricing_rules import calculate_price
```

This option is convenient when the protected module and licence are distributed together through GitHub or Azure DevOps.

### Option B: install the wheel and use the central licence folder

Install the protected wheel:

```text
python -m pip install "moduleguard_protected_pricing_rules-1.0.0-cp39-cp39-win_amd64.whl"
```

Store the licence at:

```text
%LOCALAPPDATA%\ModuleGuard\licenses\pricing-rules.lic
```

Create the folder if it does not exist. The exact location can be displayed on a publisher computer with:

```text
python -m moduleguard license-path --product-id "pricing-rules"
```

The `license-path` command is only a convenience. End users do not need ModuleGuard installed when the path and filename are supplied in the deployment instructions.

## Where ModuleGuard looks for the licence

For automatic discovery, `<product-name>.lic` below means the safe filename calculated from the exact product ID supplied during protection. It does not mean the module name, public-key name, private-key name, user name or computer name.

The protected module checks locations in this order:

1. the exact file set by `MODULEGUARD_LICENSE_FILE`;
2. the product-specific licence filename beside the loaded `.pyd`; and
3. `%LOCALAPPDATA%\ModuleGuard\licenses\<product-name>.lic`.

The first existing file is used. If that file is invalid, ModuleGuard reports the error rather than silently trying another licence.

### Explicit path override

PowerShell:

```powershell
$env:MODULEGUARD_LICENSE_FILE = "C:\CompanyLicences\pricing-rules.lic"
python "C:\Applications\run_report.py"
```

Command Prompt:

```batch
set "MODULEGUARD_LICENSE_FILE=C:\CompanyLicences\pricing-rules.lic"
python "C:\Applications\run_report.py"
```

The environment variable changes only the licence search location. It does not bypass signature, product, version, date, website or required-path checks.

## Licence duration and renewal

The issuer can use a duration:

| Value | Meaning |
| --- | --- |
| `7d` | Seven days. |
| `30d` | Thirty days. |
| `1mo` | One calendar month. |
| `6mo` | Six calendar months. |
| `1y` | One calendar year. |

If no duration or expiry is supplied, the default is `7d`.

An exact UTC expiry can be used instead:

```text
python -m moduleguard issue --product-id "pricing-rules" --private-key ".local\pricing-rules.private.pem" --product-version "1.0.0" --expires-at "2027-09-03T12:00:00Z" --output "pricing-rules.lic"
```

`--duration` and `--expires-at` cannot be used together.

To renew a licence, issue a new file and replace the old one. Restart the Python process so the module checks the replacement licence. The protected module normally does not need to be rebuilt or reinstalled.

## Obfuscation and compilation

Obfuscation runs automatically during `protect`.

ModuleGuard:

- removes comments and module, class and function docstrings;
- scrambles required positional parameters, local variables, loop variables, comprehension targets, exception variables and local import aliases;
- preserves module-level function and class names;
- preserves parameters with defaults and keyword-only parameter names;
- preserves module-level variables, attributes and methods; and
- compiles only a temporary obfuscated copy, which is deleted after the build.

For example, in `calculate_price(amount, tax=0.2)`, the public function name and `tax` parameter remain available, while `amount` and internal variables are scrambled. Both of these calls continue to work:

```python
calculate_price(100, 0.2)
calculate_price(100, tax=0.2)
```

Code that examines local names using `locals()`, `vars()`, `eval()`, `exec()`, or `compile()` receives conservative treatment, but should be tested carefully.

## GitHub and Azure DevOps guidance

A protected `.pyd` and portable licence can be stored beside tools that import the module. Bear in mind:

- anyone who can download both files can use them on another compatible computer until expiry;
- repository permissions, audit logs and branch controls become important access controls;
- use short licence periods if repository membership changes frequently;
- never commit the private signing key or its passphrase;
- do not include readable source, temporary build output or internal tests in the release; and
- a required internal URL can add a basic network check, subject to the limitations described above.

If different repositories or teams need different expiry periods or URLs, issue separate signed licences and record them in the optional issuance ledger.

## Python compatibility

Protected modules are specific to a CPython minor version and platform:

- `cp39-cp39-win_amd64` means CPython 3.9 on 64-bit Windows;
- `cp310-cp310-win_amd64` means CPython 3.10 on 64-bit Windows; and
- `cp312-cp312-win_amd64` means CPython 3.12 on 64-bit Windows.

Build and test a separate protected release with each supported Python version. Renaming a wheel or `.pyd` does not make it compatible with another Python version.

The product version must also match exactly. A module protected as `1.0.0` rejects a licence issued for `1.0.1` or `2.0.0`.

## Troubleshooting

### Licence file not found

The error lists the locations searched. Check that:

- the filename matches the product-specific filename;
- a beside-the-module licence is in the directory containing the loaded `.pyd`;
- a central licence is under `%LOCALAPPDATA%\ModuleGuard\licenses`; or
- `MODULEGUARD_LICENSE_FILE` contains the full correct path.

### Required website could not be loaded

Check the URL in the licence, internet or VPN connection, proxy configuration and website availability. The check times out after five seconds. Issue a replacement licence without `--required-url` if network presence should not be required.

### Required path is not accessible or could not be opened

Check that the path exists and that the current Windows account can open it. For a mapped drive, confirm that the drive is mapped in the same interactive or service session that runs Python. For network paths, also check the network or VPN connection and share permissions. Issue a replacement licence without `--required-path` if file-system access should not be required.

### Licence signature is invalid

The licence was changed, damaged or issued with a different private key. Restore the original file or issue a new licence. Do not edit signed licence JSON manually.

### Licence is for a different product or version

Issue a licence using the exact product ID and product version passed to `moduleguard protect`.

### Licence expired or is not valid yet

Check the Windows date, time, time zone and synchronisation. If correct, issue a replacement licence with suitable validity dates.

### Wheel is not supported on this platform

Check the Python version and architecture:

```text
python --version
python -c "import platform; print(platform.architecture())"
```

Use a wheel built for that CPython minor version and Windows architecture.

### Python imports an old or readable module

Remove obsolete copies from the application folder and Python path. To see which file Python actually imports, replace `pricing_rules` with the protected module's name and run:

```text
python -c "import pricing_rules; print(pricing_rules.__file__)"
```

The displayed path should identify the expected `.pyd`. If it instead identifies a `.py` file or an older `.pyd`, remove that copy or correct the Python path before trying again.

## Security limits

ModuleGuard is a deterrent, not unbreakable digital-rights management.

It helps to:

- exclude readable source from releases;
- remove comments and docstrings;
- obscure implementation names;
- increase reverse-engineering effort;
- prevent undetected changes to signed licence fields; and
- enforce time and optional website or file-system access checks during normal use.

It does not prevent a recipient from:

- copying a portable licence and protected module;
- inspecting inputs, outputs and behaviour;
- reverse-engineering or patching native code;
- reproducing an algorithm through testing;
- changing the local clock to weaken an offline expiry check; or
- continuing to use a module already imported into a running process.

## Command reference

All commands can be run as `moduleguard ...` or `python -m moduleguard ...`.

### Create signing keys

```text
moduleguard keygen --private-key PATH --public-key PATH
```

### Protect a module

```text
moduleguard protect --source PATH [--module-name NAME] --product-id ID --product-version VERSION --public-key PATH --output-dir PATH [--dependency REQUIREMENT ...]
```

### Issue a portable licence

```text
moduleguard issue --product-id ID --private-key PATH --product-version VERSION [--duration VALUE | --expires-at TIMESTAMP] [--required-url URL | --required-path PATH] --output PATH [--ledger PATH]
```

### Inspect a release

```text
moduleguard inspect --release-dir PATH [--forbid-text TEXT ...]
```

### Show the central licence path

```text
moduleguard license-path --product-id ID
```

Use `--help` after any command for its complete current options.
